UP.3 Programación Orientada a Objetos (POO) en PHP

En esta unidad exploraremos el paradigma de la Programación Orientada a Objetos, uno de los pilares del desarrollo de software moderno y la base sobre la que se construyen frameworks como Laravel.

Sesión 1: Fundamentos de la POO

Introducción teórica a POO

La Programación Orientada a Objetos (POO) es un paradigma de programación que organiza el código en "objetos", los cuales pueden contener tanto datos (propiedades) como comportamiento (métodos). Piensa en ello como construir con bloques de LEGO: cada tipo de bloque (clase) tiene una forma y función, y puedes crear estructuras complejas (aplicaciones) combinando esos bloques (objetos).

Clases y Objetos Básicos

Una clase es una plantilla o un molde para crear objetos. Define las propiedades y métodos que tendrán los objetos de ese tipo. Un objeto es una instancia de una clase, es decir, una "copia" concreta creada a partir de la plantilla, con sus propios valores en las propiedades.

Actividad 1: Crea tu primer guerrero.

<?php
    // 1. Define la clase Guerrero
    class Guerrero {
        // Propiedades (los datos de nuestro objeto)
        public $nombre;
        public $vida = 100;
        public $fuerza = 10;
    }
    
    // 2. Crea dos objetos (instancias) a partir de la clase
    $heroe = new Guerrero();
    $heroe->nombre = "Aragorn";
    
    $villano = new Guerrero();
    $villano->nombre = "Lurtz";
    
    // 3. Muestra sus propiedades
    echo "El héroe se llama " . $heroe->nombre;
    echo "<br>";
    echo "El villano se llama " . $villano->nombre;
    
    var_dump($heroe);
    var_dump($villano);
    ?>

Sesión 2: Dando Vida a los Objetos

Constructores, Métodos y $this

El constructor es un método especial (`__construct`) que se llama automáticamente al crear un objeto, ideal para inicializar sus propiedades. Los métodos son funciones dentro de una clase que definen su comportamiento. La pseudovariable `$this` se usa dentro de un método para referirse al propio objeto que lo está llamando.

Implementación en PHP + Encapsulación

La encapsulación es un principio clave de la POO que consiste en proteger las propiedades de un objeto para que no puedan ser modificadas desde fuera de la clase de forma incontrolada. Se usan los modificadores de acceso: `public` (accesible desde cualquier lugar), `protected` (accesible desde la clase y sus herederas) y `private` (solo accesible desde la propia clase).

Actividad 2: Mejora la clase `Guerrero`.

<?php
    class Guerrero {
        // Propiedades ahora privadas
        private $nombre;
        private $vida;
        private $fuerza;
    
        // Constructor para inicializar las propiedades
        public function __construct($nombre, $fuerza) {
            $this->nombre = $nombre;
            $this->vida = 100; // Vida inicial siempre es 100
            $this->fuerza = $fuerza;
            echo "¡" . $this->nombre . " ha entrado en combate!<br>";
        }
    
        // Método para atacar a otro guerrero
        public function atacar(Guerrero $oponente) {
            echo $this->nombre . " ataca a " . $oponente->getNombre() . ".<br>";
            $oponente->recibirDano($this->fuerza);
        }
    
        // Método para gestionar el daño recibido
        public function recibirDano($dano) {
            $this->vida -= $dano;
            echo $this->nombre . " recibe " . $dano . " de daño. Vida restante: " . $this->vida . "<br>";
        }
    
        // "Getter" para obtener el nombre (propiedad privada)
        public function getNombre() {
            return $this->nombre;
        }
    }
    
    $heroe = new Guerrero("Aragorn", 15);
    $villano = new Guerrero("Lurtz", 12);
    
    $heroe->atacar($villano);
    ?>

Sesión 3: Diseñando Nuestro Mundo

Diseño UML inicial y Relaciones entre clases (Composición)

UML (Lenguaje Unificado de Modelado) nos ayuda a diseñar visualmente la estructura de nuestras clases y cómo se relacionan. Una relación de Composición ("tiene un") ocurre cuando un objeto está compuesto por otros. Por ejemplo, un `Guerrero` "tiene un" `Arma`.

Actividad 3: ¡Equipa a tu guerrero!

<?php
    class Arma {
        private $nombre;
        private $dano;
    
        public function __construct($nombre, $dano) {
            $this->nombre = $nombre;
            $this->dano = $dano;
        }
    
        public function getDano() {
            return $this->dano;
        }
    }
    
    class Guerrero {
        // ... propiedades anteriores ...
        private $arma; // Nueva propiedad para la composición
    
        public function __construct($nombre, $fuerza) {
            // ...
        }
    
        // Método para equipar un arma
        public function equiparArma(Arma $arma) {
            $this->arma = $arma;
            echo $this->nombre . " ha equipado " . $arma->getNombre() . ".<br>";
        }
    
        public function atacar(Guerrero $oponente) {
            // El daño total ahora es la fuerza + el daño del arma
            $danoTotal = $this->fuerza + $this->arma->getDano();
            echo $this->nombre . " ataca a " . $oponente->getNombre() . ".<br>";
            $oponente->recibirDano($danoTotal);
        }
        // ... resto de métodos ...
    }
    
    $espada = new Arma("Andúril", 25);
    $heroe = new Guerrero("Aragorn", 15);
    $heroe->equiparArma($espada);
    
    $villano = new Guerrero("Lurtz", 12);
    $heroe->atacar($villano);
    ?>

Sesión 4: Familias de Clases

Herencia, Polimorfismo y Clases Abstractas

La Herencia (`extends`) permite que una clase (hija) herede propiedades y métodos de otra (padre), promoviendo la reutilización de código. El Polimorfismo es la capacidad de los objetos de diferentes clases de responder al mismo mensaje (llamada de método) de formas distintas. Una Clase Abstracta es una clase que no puede ser instanciada y sirve como base para otras clases, pudiendo forzar a sus hijas a implementar ciertos métodos abstractos.

Actividad 4: Crea la clase `Mago` y una clase base `Personaje`.

<?php
    abstract class Personaje {
        protected $nombre;
        protected $vida;
    
        public function __construct($nombre) {
            $this->nombre = $nombre;
            $this->vida = 100;
        }
    
        public function getNombre() {
            return $this->nombre;
        }
    
        // Método abstracto que las clases hijas DEBEN implementar
        abstract public function atacar(Personaje $oponente);
    }
    
    class Guerrero extends Personaje {
        protected $fuerza;
        public function __construct($nombre, $fuerza) {
            parent::__construct($nombre); // Llama al constructor del padre
            $this->fuerza = $fuerza;
        }
    
        public function atacar(Personaje $oponente) {
            echo $this->nombre . " ataca con su espada a " . $oponente->getNombre() . ".<br>";
            // ... lógica de daño ...
        }
    }
    
    class Mago extends Personaje {
        protected $mana;
        public function __construct($nombre, $mana) {
            parent::__construct($nombre);
            $this->mana = $mana;
        }
    
        public function atacar(Personaje $oponente) {
            echo $this->nombre . " lanza un hechizo a " . $oponente->getNombre() . ".<br>";
            // ... lógica de daño mágico ...
        }
    }
    
    $heroe = new Guerrero("Aragorn", 15);
    $mago = new Mago("Gandalf", 50);
    
    $heroe->atacar($mago);
    $mago->atacar($heroe);
    ?>

Sesión 5: Organizando el Código

Namespaces, Autoload y Estructura de Carpetas

Los Namespaces (espacios de nombres) evitan colisiones de nombres entre clases y organizan el código. El Autoloading es una técnica que permite cargar automáticamente los ficheros de las clases cuando se necesitan, sin tener que hacer `require` o `include` manualmente. Esto se logra con una función como `spl_autoload_register`.

Actividad 5: Organiza el proyecto en carpetas.

Crea la siguiente estructura de carpetas y mueve las clases a sus respectivos ficheros:

    /proyecto
    |-- src/
    |   |-- Personajes/
    |   |   |-- Personaje.php
    |   |   |-- Guerrero.php
    |   |   |-- Mago.php
    |   |-- Items/
    |   |   |-- Arma.php
    |-- index.php

Añade namespaces a tus clases (ej: `namespace App\Personajes;`) y usa este código en `index.php` para cargarlas:

<?php
    // index.php
    spl_autoload_register(function ($class) {
        // Convierte el namespace en una ruta de fichero
        // App\Personajes\Guerrero -> src/Personajes/Guerrero.php
        $path = 'src/' . str_replace('App\\', '', $class) . '.php';
        $path = str_replace('\\', '/', $path);
    
        if (file_exists($path)) {
            require $path;
        }
    });
    
    use App\Personajes\Guerrero;
    use App\Personajes\Mago;
    
    $heroe = new Guerrero("Aragorn", 15);
    $mago = new Mago("Gandalf", 50);
    // ...
    ?>

Sesión 6: Código a Prueba de Fallos

Excepciones y Validación Robusta

Las Excepciones son un mecanismo para manejar errores de forma controlada. Cuando ocurre un error, se "se lanza" (`throw`) una excepción, y esta puede ser "capturada" (`catch`) por un bloque de código superior para tratar el error sin que el programa se detenga bruscamente.

Actividad 6: Evita que un `Mago` equipe una `Espada`.

<?php
    // Dentro de la clase Mago
    public function equiparArma(Arma $arma) {
        // Un mago no puede equipar espadas, ¡lanzamos una excepción!
        throw new Exception($this->nombre . " es un mago y no puede equipar armas físicas.");
    }
    
    // En index.php
    $mago = new Mago("Gandalf", 50);
    $espada = new Arma("Glamdring", 30);
    
    try {
        $mago->equiparArma($espada);
    } catch (Exception $e) {
        echo "¡Error! " . $e->getMessage();
    }
    ?>

Sesión 7 (Avanzado): Contratos y Código Reutilizable

Interfaces y Traits

Una Interfaz es un "contrato" que define qué métodos debe implementar una clase, pero no cómo. Un Trait es un mecanismo para reutilizar métodos en clases independientes y no relacionadas por herencia.

Actividad 7 (Opcional): Crea una interfaz `Dañable` y un trait `ConEscudo`.

<?php
    interface Dañable {
        public function recibirDano($dano);
    }
    
    trait ConEscudo {
        public function bloquearAtaque() {
            echo $this->nombre . " bloquea el ataque con su escudo.<br>";
        }
    }
    
    // La clase Personaje ahora implementa la interfaz
    abstract class Personaje implements Dañable {
        // ...
    }
    
    // La clase Guerrero ahora usa el trait
    class Guerrero extends Personaje {
        use ConEscudo;
        // ...
    }
    
    $heroe = new Guerrero("Boromir", 20);
    $heroe->bloquearAtaque(); // Método del Trait
    ?>

Sesión 8: El Combate Completo

Actividad Final Integradora

¡Es hora de juntar todas las piezas! Crea un script `combate.php` que haga lo siguiente:

  1. Crea una instancia de `Guerrero` y una de `Mago`.
  2. Equipa a cada uno con su arma o poder correspondiente.
  3. Simula un combate por turnos usando un bucle `while`.
  4. En cada turno, un personaje ataca al otro.
  5. El combate termina cuando la vida de uno de los dos llega a 0 o menos.
  6. Muestra un mensaje con el ganador del combate.

Este ejercicio final te obligará a usar objetos, herencia, polimorfismo y la gestión del estado de los objetos para crear una pequeña simulación funcional.
