Entendiendo el Backtracking con Metáforas

¿Qué es el Backtracking? (Introducción Teórica)

El backtracking, o vuelta atrás, es una técnica de diseño de algoritmos para resolver problemas de manera sistemática. Se basa en los siguientes pasos:

  1. Explorar: Se construye una solución paso a paso. En cada paso, se elige una opción entre varias posibles.
  2. Validar: Se comprueba si la elección actual puede conducir a una solución válida.
  3. Retroceder (Backtrack): Si la elección no es válida o lleva a un callejón sin salida, se deshace esa elección y se prueba la siguiente opción disponible en el paso anterior.
  4. Finalizar: El proceso termina cuando se encuentra una solución completa o cuando se han explorado todas las posibilidades sin éxito.

Es especialmente útil en problemas de optimización y de satisfacción de restricciones, como puzzles, juegos y planificación.

Análisis de las Metáforas según la Teoría

Siguiendo las directrices vistas en clase sobre el uso de metáforas en la enseñanza de la informática, vamos a analizar el enfoque que hemos utilizado.

Tipo de Organizador

Las metáforas del laberinto y del árbol de decisiones actúan como un organizador previo de tipo comparativo. La razón es que no partimos de cero; un estudiante de DAM ya tiene conocimientos sobre lo que es un laberinto o un árbol. La metáfora no presenta un concepto general nuevo (como haría un organizador expositivo), sino que establece vínculos y paralelismos entre ese conocimiento previo y familiar (el laberinto) y el concepto nuevo y abstracto que queremos explicar (el algoritmo de backtracking).

Naturaleza del Concepto

El concepto a explicar es el "backtracking". Según la clasificación del PDF, la naturaleza de este concepto se puede considerar como algo tangible. Aunque un algoritmo es abstracto, el PDF usa como ejemplo de concepto tangible la "memoria dinámica", que también es abstracta pero se puede describir a través de sus elementos (punteros, celdas) y las acciones que se realizan sobre ellos (asignar, liberar).

De la misma forma, el backtracking es un proceso con elementos y acciones definibles:

  • Elementos (Sustantivos): Un estado inicial, nodos, caminos, decisiones, una solución parcial, una solución final.
  • Acciones (Verbos): Explorar un camino, validar una decisión, añadir a la solución, retroceder (backtrack), encontrar una solución.

Al poder descomponer el concepto en estas partes y acciones concretas, podemos aplicar una metáfora sobre un concepto tangible, como es la del laberinto, donde también hay elementos (caminos, muros, salida) y acciones (avanzar, volver atrás).

La Metáfora del Laberinto

La estrategia para resolver un laberinto es un ejemplo perfecto de backtracking. A continuación, enlazamos los elementos del mundo real con los conceptos informáticos:

  • Elemento real: Estar perdido en un laberinto.
    Elemento informático: El estado inicial de un problema a resolver.
  • Elemento real: Elegir un camino en una intersección.
    Elemento informático: Probar una posible solución parcial.
  • Elemento real: Dejar una marca para no repetir el camino.
    Elemento informático: Marcar un nodo como "visitado" para no entrar en bucles.
  • Elemento real: Llegar a un callejón sin salida.
    Elemento informático: Darse cuenta de que la solución parcial actual no es válida.
  • Elemento real: Volver sobre tus pasos hasta la última intersección.
    Elemento informático: Realizar backtrack, deshaciendo la última decisión y volviendo al estado anterior.
  • Elemento real: Encontrar la salida.
    Elemento informático: Encontrar una solución completa y válida al problema.

Ejemplo en Pseudocódigo


funcion resolverLaberinto(posicionActual):
  // Caso base: Si hemos encontrado la salida, ¡éxito!
  si posicionActual es la SALIDA:
    retornar verdadero

  // Marcamos la celda actual como visitada para no volver a pasar por ella.
  marcar posicionActual como VISITADA

  // Exploramos los caminos posibles (Norte, Sur, Este, Oeste)
  para cada proximoPaso adyacente a posicionActual:
    // Si el camino es válido (no es una pared y no ha sido visitado)
    si proximoPaso es valido:
      // Movemos al siguiente paso (descendemos por la "rama")
      si resolverLaberinto(proximoPaso) es verdadero:
        retornar verdadero // La solución fue encontrada por este camino

  // Si ningún camino desde aquí lleva a la salida, hacemos backtrack.
  // En el contexto del laberinto, no es necesario "desmarcar" la celda
  // si solo buscamos un camino, pero en otros problemas es clave.
  retornar falso // Indicamos que este camino fue un callejón sin salida

La Metáfora del Árbol de Decisiones

También podemos ver el problema como un árbol de decisiones, donde cada rama es una elección.

  • Elemento real: El tronco del árbol.
    Elemento informático: El estado inicial del problema (la raíz).
  • Elemento real: Una rama que sale de un nudo.
    Elemento informático: Una posible decisión o paso a seguir.
  • Elemento real: Una hoja del árbol.
    Elemento informático: Un resultado final (puede ser una solución válida o no).
  • Elemento real: Bajar por una rama hasta llegar a una hoja seca (sin fruto).
    Elemento informático: Explorar una secuencia de decisiones que no lleva a una solución.
  • Elemento real: "Podar" esa rama seca y volver al nudo anterior para bajar por otra.
    Elemento informático: Descartar la rama de decisiones no válida y retroceder para explorar una alternativa.

Ejemplo en Pseudocódigo


funcion resolverConBacktracking(solucionParcial):
  // Caso base: Si la solución parcial ya es una solución completa y válida.
  si solucionParcial es una SOLUCION_COMPLETA:
    mostrar solucionParcial
    retornar verdadero

  // Generamos las posibles decisiones/ramas para el siguiente paso.
  para cada proximaDecision posible:
    // 1. Tomar la decisión (avanzar por la rama).
    añadir proximaDecision a solucionParcial

    // 2. Validar: ¿Es una decisión prometedora?
    si solucionParcial es VALIDA:
      // 3. Explorar: Llamada recursiva para seguir construyendo la solución.
      si resolverConBacktracking(solucionParcial) es verdadero:
        retornar verdadero // Se encontró una solución por esta rama.

    // 4. Retroceder (Backtrack): Si la decisión no fue buena o no llevó a una solución.
    // Es como "podar" la rama del árbol. Se deshace el paso anterior.
    quitar proximaDecision de solucionParcial

  // Si ninguna decisión desde este punto llevó a una solución.
  retornar falso

El Problema de las 8 Reinas

Un ejemplo famoso es el "Problema de las 8 Reinas", donde tienes que colocar 8 reinas en un tablero de ajedrez sin que ninguna pueda atacar a otra.

El algoritmo de backtracking haría lo siguiente:

  1. Coloca la primera reina en la primera casilla.
  2. Coloca la segunda reina en la primera casilla segura de la siguiente fila.
  3. Continúa así. Si en algún momento no puede colocar una reina en una fila, retrocede a la fila anterior y mueve la reina de esa fila a una nueva posición segura.
  4. Repite el proceso hasta que las 8 reinas estén en el tablero.
